## 一、伊迪丝系统（核心）

### 什么是伊迪丝

伊迪丝是一个基于古代中国三省六部制架构的智能助手系统。不是普通的聊天机器人，而是有组织架构、有决策流程、有知识积累的"AI参谋部"。

### 部门架构

```
决策层：伊迪丝（总参谋，拍板决策）
├── 决策支持层
│   └── 市场运营部（需求分析、市场洞察）
├── 执行层
│   ├── 工部（代码开发、技术实现）
│   ├── 美术设计（视觉设计、UI风格）
│   ├── 交互设计（交互逻辑、用户体验）
│   ├── 户部（数据核算、统计分析）
│   ├── 视频创作部（脚本、分镜、剪辑）
│   └── 通商部（联网搜索、信息收集）
└── 审核层（按需触发）
    ├── 刑部（安全审核、权限校验）
    └── 门下省（合规审核、对外输出）
```

### 四轮商讨机制

伊迪丝处理复杂任务的标准流程：

1. **理解**：伊迪丝解析用户真实需求，不急于给答案
2. **第一轮商讨**：各部门独立分析，输出初步方案
3. **对话讨论**：5轮对话深入探讨，碰撞优化
4. **第三轮商讨**：综合评判，选出最优方案
5. **确认→执行→交付**：用户确认后派发执行

灵感来自唐代政事堂制度——重大决策需要中书省起草、门下省审核、尚书省执行，三权分立确保决策质量。

### 技术特色

- **知识库驱动**：每个部门有专业知识库，执行任务时自动注入
- **分级审核**：低/中/高风险任务差异化处理
- **可视化监控**：实时面板展示商讨过程
- **记忆持久化**：跨会话记忆，200行上限+归档SOP

## 二、ProSearch搜索工具

### 问题背景

传统浏览器搜索方式太贵太慢：
- browser工具返回完整DOM，单次搜索消耗25000-40000 token
- 多次浏览器调用，耗时50-90秒

### 解决方案

构建ProSearch多引擎搜索聚合工具，核心思路：**curl优先，browser兜底**。

### 三级降级机制

| 级别 | 方式 | token消耗 | 适用场景 |
|------|------|-----------|----------|
| 第一级 | curl静态提取 | ~300 | 文档站、GitHub等静态页面 |
| 第二级 | curl高级提取 | ~800 | 动态页面，模拟浏览器请求 |
| 第三级 | browser精准提取 | ~1500 | JS重度渲染页面 |

### 搜索引擎支持

- **DuckDuckGo**：国际搜索，无需API key
- **必应中国版**：国内搜索，HTML解析
- **百度**：国内搜索，反爬优化（代理轮换、验证码降级、2-5秒随机延迟）

### 性能对比

| 方案 | token消耗 | 耗时 | 节省 |
|------|-----------|------|------|
| 纯浏览器 | 25000-40000 | 50-90秒 | - |
| **ProSearch** | 2100 | 6秒 | **95%** |

### 实际测试

搜索"Cloudflare WARP最新版本更新"：
- 返回3个结果，含完整内容提取
- 总耗时6.33秒
- token消耗2100
- 同样的任务，纯浏览器需要50-90秒，消耗25000-40000 token

## 三、知识库体系

### 设计理念

伊迪丝的"专业性"来自知识库。不是每次请求都加载所有知识，而是**按需注入**——只有当任务涉及某个部门时，才注入该部门的相关知识。

| 交互设计 | 4个 | 交互设计原则、交互动效、UX方法论、UI交互模式 |
| 工部 | 6个 | 代码质量、前端/后端、调试测试、性能优化、Git工程化 |
