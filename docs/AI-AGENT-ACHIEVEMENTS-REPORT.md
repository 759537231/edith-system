## 一、核心系统：伊迪丝（EDITH）

伊迪丝是一个基于古代中国三省六部制架构的智能助手系统。与传统AI助手不同，伊迪丝采用"部门制"组织架构，将复杂任务分解到不同专业部门协同完成。

**架构设计**：
```
决策层：伊迪丝（总参谋，拍板决策）
├── 决策支持层：市场运营部（需求分析、市场洞察）
├── 执行层：工部（代码）、美术设计（视觉）、交互设计（UX）、户部（数据）、视频创作部（脚本）、通商部（信息收集）
└── 审核层：刑部（安全）、门下省（合规）——按需触发
```

**四轮商讨机制**是伊迪丝的核心决策流程：
1. **理解**：伊迪丝解析用户真实需求
2. **第一轮商讨**：各部门独立分析，输出初步方案
3. **对话讨论**：5轮对话深入探讨，碰撞优化
4. **第三轮商讨**：综合评判，选出最优方案
5. **确认→执行→交付**：用户确认后派发执行

这套机制的灵感来自唐代政事堂制度——重大决策需要中书省起草、门下省审核、尚书省执行，三权分立确保决策质量。

**技术亮点**：
- **知识库驱动**：每个部门配备专业知识库（美术设计有色彩理论、中国传统色彩；工部有代码质量规范、Git工作流），子Agent执行任务时自动注入相关知识，零额外token消耗
- **Prompt Cache优化**：删除系统提示中的时间戳注入，使前缀保持稳定，切换DeepSeek后缓存命中价享受98%折扣
- **MEMORY生命周期管理**：200行上限+写入前检测+归档SOP，MEMORY.md从28KB精简到4KB，每次请求token消耗大幅降低

## 二、ProSearch：多引擎搜索聚合工具

**问题背景**：传统浏览器搜索方式存在两大痛点——browser工具返回完整DOM结构，单次搜索消耗25000-40000 token；多次浏览器调用，耗时50-90秒。这在需要频繁搜索的场景下成本极高。

**解决方案**：构建ProSearch多引擎搜索聚合工具，核心思路是"curl优先，browser兜底"。

**三级降级机制**：
1. **curl静态提取**：对docs.cloudflare.com、github.com等静态站点，直接用curl抓取HTML，提取正文，token消耗仅~300
2. **curl高级提取**：对动态页面，模拟浏览器User-Agent请求，自动过滤nav/header/footer等非内容区域，token消耗~800
3. **browser精准提取**：对JavaScript重度渲染页面，用browser_console执行脚本精准提取，token消耗~1500

**搜索引擎支持**：
- **DuckDuckGo**：国际搜索，无需API key
- **必应中国版**：国内搜索，HTML解析
- **百度**：国内搜索，反爬优化（代理轮换、验证码降级、2-5秒随机延迟、连续失败3次自动禁用）

**缓存机制**：SQLite本地缓存，1小时TTL，相同查询秒回（0.00秒）。

**性能对比**：

| 方案 | token消耗 | 耗时 | 节省 |
|------|-----------|------|------|
| 纯浏览器 | 25000-40000 | 50-90秒 | - |
| ProSearch | 2100 | 6秒 | 95% |

实际测试："Cloudflare WARP最新版本更新"搜索，ProSearch返回3个结果（含完整内容提取），总耗时6.33秒，token消耗2100。同样的任务，纯浏览器方式需要50-90秒，消耗25000-40000 token。

## 三、知识库体系

伊迪丝为每个执行部门建立了专业知识库，这是系统"专业性"的来源。子Agent执行任务时，`knowledge_injector.py`自动扫描部门知识库，根据任务关键词匹配相关知识并注入上下文。

**知识库规模**：

| 部门 | 文件数 | 核心内容 |
|------|--------|----------|
| 美术设计 | 4个 | 色彩理论、中国传统色彩、排版构图、设计风格历史 |
| 交互设计 | 4个 | 交互设计原则、交互动效、UX方法论、UI交互模式 |
| 工部 | 6个 | 代码质量、前端/后端、调试测试、性能优化、Git工程化 |
| 户部 | 4个 | 统计学、数据可视化、Excel与SQL、财务分析 |
| 市场运营部 | 4个 | 用户研究、市场分析、产品设计、运营策略 |
| 视频创作部 | 4个 | 脚本写作、分镜设计、构图原则、运镜与剪辑 |

**知识注入机制**：零额外token消耗。知识不是每次请求都加载，而是按需注入——只有当任务涉及某个部门时，才注入该部门的相关知识。
