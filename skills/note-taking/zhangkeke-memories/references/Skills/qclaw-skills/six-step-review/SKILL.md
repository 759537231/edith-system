# 六步复盘框架

用于项目完成、事件结束、阶段性验收时的结构化总结。

## 框架

```
① 目的   — 要达到什么目标
② 措施   — 具体做了什么
③ 定性   — 属于什么性质（好/坏/必要/多余/超预期）
④ 反思   — 做完之后有什么感受和收获
⑤ 剖析原因 — 为什么会是这个结果
⑥ 结果   — 最终产出了什么
```

## 使用场景

| 场景 | 侧重 |
|------|------|
| 项目完成 | ③定性 + ⑥结果为主 |
| 任务失败 | ⑤剖析原因 + ④反思为主 |
| 阶段性验收 | ①目的 + ②措施 + ⑥结果为主 |
| 日常工作总结 | ②措施 + ⑥结果为主 |

## 输出格式

面向用户，自然语言。根据场景灵活调整各部分的权重：

```
【复盘】{项目/事件名称}

① 目的：{一句话}
② 措施：{做了什么}
③ 定性：{属于什么性质，一句话评价}
④ 反思：{收获了什么，有什么可以改进}
⑤ 剖析原因：{为什么是这个结果，根本原因是什么}
⑥ 结果：{最终产出}

【下一步】{基于复盘的后续计划}
```

## 关键原则

1. **实事求是** — 不夸大成绩，不回避问题
2. **先说结论** — 定性和结果放前面，细节放后面
3. **根因分析** — 反思不能停留在"哪里做得不好"，要挖到"为什么会这样"
4. **可行动** — 复盘的结论要能指导下一步行动，不能沦为空谈
5. **灵活调整** — 六步全部走完是最完整的，但简单任务可以只走3-4步
