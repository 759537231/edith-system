## 2026-05-08 误诊根因 + 重试死循环

### 问题：工具连续失败时错误归因

**用户反馈**：
- "你消失了"
- "我刚刚用qclaw把你修好了"

**现象**：
1. 工具连续6次 `[Command interrupted]`
2. 我诊断为"你发消息打断了我"
3. 实际原因：我自己卡死了，需要qclaw修复
4. 我重试了6次同样的方式，没有降级

**根因分析**：
- 把 `[Command interrupted]` 等同于"用户打断"
- 没有区分"被中断"和"自己卡死"两种情况
- 重试策略错误：连续6次用同样的方式重试

**正确做法**：
```
工具失败
  ├── 第1次失败 → 检查命令是否正确
  ├── 第2次失败 → 换一种方式（不同工具/不同命令）
  ├── 第3次失败 → 停止，告诉用户"我遇到问题"
  └── 不要超过3次重试
```

**工具优先级**：
1. `execute_code` — 最不容易中断，适合批量操作
2. `write_file` — 适合单个文件
3. `terminal` — 最容易被中断，只用于简单命令

**铁律**：
1. **不要假设失败原因**。`[Command interrupted]` 不等于"用户打断"。
2. **3次失败必须停止**。重试超过3次，立即换方式或求助。
3. **诊断和解决是两件事**。先搞清楚为什么失败，再决定怎么做。

## 2026-05-08 可视化系统设计

### 任务：为伊迪丝系统设计可视化界面

**研究结论**：
- AutoGen、CrewAI、LangGraph三大框架都选Web界面
- 没有选终端TUI的
- 原因：多代理系统需要实时刷新、图状展示、历史回溯

**设计方案**：
- 后端：Python Flask + SSE（Server-Sent Events）
- 前端：纯HTML/CSS/JS，无框架依赖
- 功能：阶段流程、部门状态、三轮商讨、进度追踪、历史记录

**开发过程中的问题**：
- 工具连续6次中断（误诊为用户打断，实际是自己卡死）
- delegate_task超时（600秒限制）
- 端口8080被占用
- 最终未完成，需要继续

**教训**：
1. 开发Web应用时，用 `execute_code` 一次性创建所有文件
2. 不要用 `write_file` 一个一个写
3. 端口冲突时自动查找可用端口
4. delegate_task不适合长时间运行的任务
