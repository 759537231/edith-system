# 多代理框架对比与伊迪丝改进方向

> 基于 AutoGen (57.8k⭐)、CrewAI (1.8万⭐)、LangGraph (1.2万⭐) 三大框架的研究。
> 更新日期：2026-05-08

## 一、三大框架核心特点

### AutoGen（微软）57.8k⭐
- **团队模式**：RoundRobinGroupChat（轮询）、SelectorGroupChat（选择器）、MagenticOneGroupChat、Swarm（群体）
- **核心理念**：共享上下文 + 集中式调度
- **杀手功能**：
  - Human-in-the-Loop（人机协作，可在任意节点插入人工审核）
  - Termination Conditions（智能终止条件，不是固定轮数）
  - Custom Agents（自定义代理，可扩展行为）
  - Memory and RAG（记忆+检索增强）
- **架构**：Agent → Team → Group Chat，消息驱动

### CrewAI 1.8万⭐
- **角色系统**：每个Agent有明确的 Role / Goal / Backstory
- **记忆系统**（三层架构）：
  - 短期记忆：当前会话上下文
  - 长期记忆：跨会话持久化（RAG-based）
  - 实体记忆：用户/项目/关系图谱
- **知识库**：支持外部知识注入（文档/URL/API）
- **技能系统**：可复用的 Skills 模块（类似伊迪丝的skills）
- **流程控制**：Flows 支持条件路由和分支
- **MCP集成**：原生支持 MCP 协议的工具接入
- **架构**：Agent → Task → Crew → Flow，任务驱动

### LangGraph 1.2万⭐
- **图状工作流**：Node（节点）+ Edge（边）+ 条件路由
- **状态管理**：
  - 持久化状态（Persistence）
  - 可回溯（Time Travel）
  - 断点续传（Checkpointing）
- **容错机制**：故障恢复、重试策略
- **子图支持**：模块化嵌套，复杂流程可分解
- **中断机制**：支持在任意节点暂停等待人工输入
- **架构**：Graph → State → Node → Edge，状态驱动

## 二、伊迪丝可借鉴的设计

### 1. 记忆系统升级（借鉴CrewAI）
**当前状态**：单一memory工具，无分层
**改进方向**：
```
三层记忆架构
├── 短期记忆：当前会话上下文（已有）
├── 长期记忆：跨会话持久化（已有memory工具，需结构化）
└── 实体记忆：用户/项目/关系图谱（缺失，需新增）
```
**具体做法**：
- 为每个项目/用户维护实体卡片
- 关系图谱：用户偏好 → 项目关联 → 历史决策链
- 长期记忆按主题索引，支持语义检索

### 2. 状态管理（借鉴LangGraph）
**当前状态**：对话式，无显式状态机
**改进方向**：
```
显式状态机
├── 理解阶段 → 可暂停
├── 商讨阶段 → 可回退到理解
├── 确认阶段 → 可回退到商讨
├── 执行阶段 → 可暂停/恢复
└── 交付阶段 → 只读
```
**具体做法**：
- 为每个伊迪丝任务维护状态对象
- 支持"回到上一步"操作
- 状态持久化，会话断开后可恢复

### 3. 终止条件（借鉴AutoGen）
**当前状态**：三轮商讨固定流程
**改进方向**：
```
智能终止判断
├── 共识达成 → 提前终止（不强制走满三轮）
├── 陷入僵局 → 升级处理（引入外部视角）
├── 用户干预 → 立即停止
└── 超时保护 → 自动降级
```
**具体做法**：
- 第一轮后评估：如果双方高度一致，可跳过第二轮独立出方案
- 第二轮后评估：如果方案差异<20%，可简化第三轮
- 设置最大商讨时间，超时自动降级为直接执行

### 4. 知识注入（借鉴CrewAI）
**当前状态**：skills文件系统，按需加载
**改进方向**：
```
结构化知识库
├── 项目知识：项目文档/历史决策/架构图
├── 领域知识：行业知识/最佳实践/案例库
└── 用户知识：偏好/习惯/约束/关系
```
**具体做法**：
- 为每个长期项目维护知识目录
- 领域知识按行业/主题分类
- 用户知识自动从对话中提取并结构化

### 5. 子图/子流程（借鉴LangGraph）
**当前状态**：部门独立工作，无嵌套流程
**改进方向**：
```
可嵌套的工作流
├── 复杂任务 → 分解为子流程
├── 子流程可并行执行
├── 子流程可递归嵌套
└── 结果自动聚合
```
**具体做法**：
- 定义标准子流程模板（搜索→分析→输出）
- 子流程支持嵌套（一个部门内部可再拆分）
- 子流程结果自动合并到父流程

## 三、优先级建议

### 高优先级（立即可做）
1. **终止条件** — 三轮商讨可以提前结束，节省时间和token
2. **状态可视化** — 让用户看到当前在哪个阶段，支持"回到上一步"

### 中优先级（版本迭代）
3. **记忆分层** — 短期/长期分离，实体记忆新增
4. **知识注入** — 支持外部文档作为知识源

### 低优先级（长期规划）
5. **图状工作流** — 架构大改，需要重构执行引擎
6. **子图嵌套** — 模块化复杂任务，需要先完成状态管理

## 四、关键洞察

1. **伊迪丝的部门制是独特优势** — 三大框架都是扁平代理列表，伊迪丝的层级组织+商讨机制是差异化
2. **记忆系统是最大短板** — CrewAI的三层记忆架构值得深度借鉴
3. **状态管理是工程化关键** — LangGraph的状态机设计让复杂任务可追踪、可回退
4. **终止条件影响效率** — AutoGen的智能终止可大幅节省token消耗
5. **中文市场机会** — 三大框架都是英文优先，伊迪丝可以做中文多代理系统的标杆
