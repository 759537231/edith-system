## 二、系统特点

1. **模块低耦合**：每个服务独立进程/模块，通过API或消息队列通信
2. **按需扩展**：可单独替换某个模块（如换掉Whisper为其他STT）
3. **macOS arm64 优先**：所有依赖均验证 arm64 兼容性
4. **流式友好**：WebSocket 支持实时任务进度推送
5. **本地优先**：不强制依赖云服务，可完全离线运行

## 三、技术选型

| 模块 | 技术选型 | 理由 |
|------|---------|------|
| 前端 | Streamlit 1.38+ | 与现有结算系统一致，Python 原生 |
| API | FastAPI 0.115+ | 高性能 async，Swagger 自动生成，类型安全 |
| 音频处理 | Pydub + ffmpeg | 格式转换/切割/合并，支持所有常见格式 |
| 语音转文字 | Whisper (openai-whisper) | 本地运行，macOS arm64 优化，准确率高 |
| 向量检索 | FAISS (faiss-cpu) | Facebook 开源，支持百万级向量，macOS 友好 |
| 文本嵌入 | sentence-transformers | 多语言支持，macOS 可用，MIT 许可证 |
| 数据库 | SQLite + SQLAlchemy 2.0 | 无服务器进程，事务安全，ORM 友好 |
| 任务队列 | asyncio + threading (轻量) / RQ (可选) | 小规模用 asyncio 足够，大规模可上 RQ |
| 角色识别 | 自研特征提取 + sklearn | 无需购买商业 API，本地可控 |
| 声音克隆 | Coqui-TTS / Tortoise-TTS | 开源可选，macOS 兼容，CPU 可运行 |
| 配置管理 | PyYAML + Pydantic | 声明式配置，类型验证 |

## 四、数据流

```
[MP3/WAV上传]
    ↓
[文件验证 + 格式检测] → 写入 raw_audio/
    ↓
[音频处理管道] → 分轨/降噪/标准化
    ↓
[Whisper STT] → 文字 transcript + 时间戳
    ↓
[角色识别] → 说话人分离 + 角色标注
    ↓
[向量嵌入] → FAISS 索引
    ↓
[智能剪辑推荐] → 时间轴切点建议
    ↓
[输出] → 处理后音频 + 元数据JSON + 结算记录
```

## 五、模块依赖关系

- `streamlit_app` → 依赖 `api`, `db`
- `api` → 依赖 `services/*`, `db`
- `services/audio_pipeline` → 依赖 `services/transcription`
- `services/transcription` → 依赖 `db`（写记录）
- `services/role_recognition` → 依赖 `services/transcription` 的结果
- `services/embedding_search` → 独立，可热更新
