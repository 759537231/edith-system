# MEMORY.md 生命周期管理

## 铁律

**写入前必检查**：调用memory工具写入MEMORY.md前，先用terminal执行：
```bash
wc -l ~/.hermes/MEMORY.md
```
- **<200行**：正常写入
- **≥200行**：先执行归档SOP，再写入

**壳壳模式**：MEMORY.md超过200行时，被动提醒用户："MEMORY.md已超200行，建议清理。"不强制归档。

**伊迪丝模式**：MEMORY.md超过200行时，在商讨流程第一步自动插入"MEMORY审查"环节，执行归档SOP后再进入正式商讨。

## 归档SOP

当MEMORY.md超过200行/10KB时，执行以下流程：

```
1. 读取 MEMORY.md 全文
2. 按以下标准分类每条记忆：
   ├── 活跃 → 保留在MEMORY.md
   ├── 已完成/已终止/已搁置 → 移入archive.md
   ├── 信息性/无行动项 → 移入archive.md
   └── 不确定 → 保留（宁可多留不可多删）
3. 移入archive.md的条目：
   - 在MEMORY.md中保留一行摘要（含状态和创建日期）
   - 完整内容移入archive.md对应章节
4. 验证：
   - MEMORY.md < 200行
   - archive.md包含所有被移出的完整内容
   - 无信息丢失
```

## 格式规范

每条记忆格式：
```
- 内容摘要（创建:YYYY-MM-DD）
```

详情放archive.md，MEMORY.md只存一行摘要。

## 三层架构

```
MEMORY.md（活跃层，<200行）
    ↓ 超限时归档
archive.md（归档层，无限）
    ↓ 过时且无价值
删除（不保留）
```

## 触发时机

| 场景 | 检测方式 | 动作 |
|------|---------|------|
| 伊迪丝写入memory | `wc -l`检查 | 超限则先归档再写入 |
| 壳壳写入memory | `wc -l`检查 | 超限则提醒用户 |
| 伊迪丝商讨任务前 | `wc -l`检查 | 超限则在商讨前插入MEMORY审查 |
| 用户说"清理一下" | 手动触发 | 执行归档SOP |

## 注意事项

- 归档操作本身不消耗LLM token（纯文件操作）
- 不搞cron/heartbeat定期任务
- archive.md是备份，不是垃圾箱——移入的条目保留完整内容
- 创建日期不准确的条目用"未知"标注
