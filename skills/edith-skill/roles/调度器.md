# 调度器（Dispatch）— 伊迪丝并行执行引擎（Hermes 版）

> 本文件由伊迪丝主会话调用，作为多部门任务的执行中枢。
> 不单独运行，只在SKILL.md判定"进入模式B"时激活。
>
> **适配说明**：本版本已从 QClaw 的 delegate_task 适配为 Hermes 的 delegate_task。

---

## 职责定位

```
用户请求 → 伊迪丝主会话（枢密院模式）
               ↓ 判断：复杂度
               ↓ 触发：调度器（多部门协作时）
               
               ┌→ 判断部门组合（哪些需要委派）
               ├→ 判断并行关系（哪些可以同时）
               ├→ 构建委派任务（每个部门的独立指令）
               ├→ 执行 delegate_task（真正并行）
               ├→ 等待所有结果（超时控制）
               ├→ 汇总输出（结构化报告）
               └→ 送审（督察院/门下省，按需）

               ↓ 交付用户
```

---

## Step 1：委派决策树

### 决策输入

```
【原始任务】：{用户描述}
【识别到的部门】：[部门A, 部门B, 部门C, ...]
【部门间依赖】：{谁依赖谁的结果}
【风险等级】：低 / 中 / 高
```

### 决策规则

**必须委派（并行模式）**：
- 3+部门且无强依赖 → 全委派并行
- 3+部门有依赖链 → 分组：先做无依赖的，并行跑；再做有依赖的
- 高风险（对外动作）→ 必须委派门下省复核

**不应委派（模拟模式更高效）**：
- 2个部门且无依赖 → 模拟更轻
- 纯搜索/纯问答 → 模拟即可
- 用户说"简单做" → 强制模拟

### 部门并行关系速查

| 部门组合 | 关系 | 建议 |
|---------|------|------|
| 工部 + 产品部 | 常独立 | 可并行 |
| 工部 + 通商部 | 常独立 | 可并行 |
| 产品部 + 通商部 | 常独立 | 可并行 |
| 枢密院 + 其他 | 枢密院在前 | 必须先跑完，再并行其他 |
| 督察院（质量） | 最后 | 必须最后，其他全完成后再跑 |
| 门下省（复核） | 最后 | 必须最后，其他全完成后再跑 |

## Step 2：构建委派任务

### 格式

每个子Agent的任务描述包含：

```
【任务ID】：{部门}-{序号}（如 工部-001）
【当前时间】：{YYYY-MM-DD HH:mm GMT+8}
【你是】：{部门名}，伊迪丝总参谋模式，独立子Agent

【上下文隔离 — 重要】
- 你的上下文与主会话完全隔离
- 只使用任务描述中明确写出的信息
- 不猜测，不知道就说"任务中未给出"
- 完成后直接输出分析结论，不要重复任务描述

【原始任务】：{用户需求}
【本部门任务】：{从原始任务中提取的本部门职责}
【输出规范】：见下方部门输出底线
【完成后返回】：{任务ID}、{状态：success/partial/failed}、{摘要（50字内）}、{详情}、{建议下一步}
```

### 部门输出底线（必须内嵌到每个委派任务里）

| 部门 | 输出底线 |
|------|---------|
| 枢密院 | 必须给出战略判断+部门拆解 |
| 产品部 | 必须给出需求本质+方案+验收标准 |
| 工部 | 两阶段：①架构：目录+Schema+函数签名 ②实现：核心模块代码 |
| 通商部 | 必须给结论，哪怕信息不足也要给方向性判断 |
| 户部 | JSON输出，必须含数据来源 |
| 刑部 | JSON输出（仅高风险触发） |
| 督察院 | JSON裁决（所有伊迪丝任务触发） |
| 门下省 | JSON复核（仅对外动作触发） |

### 依赖注入规范

当部门间存在依赖链时：

**第一步**：在构建下游部门任务时，在【原始任务】之后插入依赖注入块：

```
【依赖注入】（来自 {上游部门}-{序号} 的结论）
- 核心判断/结论：{从上游结果中提取的关键内容}
- 对本部门的直接影响：{具体说明下游需要注意什么}
```

**第二步**：注入内容来源——从枢密院的【任务拆解方案】中提取结论，手工写入下游任务描述。

**第三步**：若上游超时——
- 枢密院超时 → 停止整个任务，上报用户
- 其他上游超时 → 标记为 partial，下游用已知信息继续

### 最大并行数

**不超过4个同时委派**。超过4个部门时分批次。

## Step 3：delegate_task 调用格式（Hermes 适配）

### 标准调用

```python
delegate_task(
    goal="【任务ID：工部-001】{完整任务描述}...",
    context="伊迪丝总参谋模式，{部门名}子Agent。{额外上下文}",
    toolsets=["web", "terminal", "file"]  # 按需选择
)
```

### 批量并行调用

```python
delegate_task(tasks=[
    {"goal": "枢密院任务...", "context": "伊迪丝枢密院"},
    {"goal": "工部任务...", "context": "伊迪丝工部"},
    {"goal": "产品部任务...", "context": "伊迪丝产品部"},
])
```

### 典型委派场景

**场景A：3个独立部门并行**

```
用户任务：设计客户报价自动化方案

识别部门：枢密院（分析）、工部（技术方案）、产品部（市场评估）
依赖关系：无强依赖，可以并行

delegate_task(tasks=[
    {"goal": "枢密院任务...", "context": "伊迪丝枢密院"},
    {"goal": "工部任务...", "context": "伊迪丝工部"},
    {"goal": "产品部任务...", "context": "伊迪丝产品部"},
])

等待全部完成后 → 汇总 → 送审（如需要）→ 交付
```

**场景B：有依赖链（枢密院先跑）**

```
用户任务：复杂技术调研+方案+实现

识别部门：枢密院 → 工部 → 通商部
依赖：枢密院结论影响工部方向

第一轮（枢密院单独）：
  delegate_task(goal="枢密院任务...", context="伊迪丝枢密院")

枢密院完成后 → 分析结论 → 注入工部任务

第二轮（工部+通商部并行）：
  delegate_task(tasks=[
      {"goal": "工部任务（含枢密院结论）...", "context": "伊迪丝工部"},
      {"goal": "通商部任务（含枢密院结论）...", "context": "伊迪丝通商部"},
  ])

等待全部完成 → 汇总 → 交付
```

## Step 5：审核分级

| 风险等级 | 判定标准 | 审核链 |
|---------|---------|--------|
| 🟢 低风险 | 纯内部/只读 | 跳过审核 |
| 🟡 中风险 | 对外输出/修改文件 | 督察院一审 |
| 🔴 高风险 | 对外动作/删改/涉隐私 | 完整审核（刑部→督察院→门下省） |

---

## Step 6：错误处理

```
错误发生
  ├── 单部门失败（非关键路径）→ 标记failed，继续
  ├── 单部门失败（关键路径）→ 停止任务
  ├── 部门超时 → 按决策树处理
  ├── 刑部拦截 → 停止，告知用户
  ├── 督察院驳回 → 重做（最多3次）
  └── 3次重试仍失败 → 停止整个任务
```

## 独立部门Skill调用规范（2026-05-08）

### 调用方式

伊迪丝通过 `delegate_task` 调用独立部门skill，子Agent在隔离上下文中执行任务。

### 调用流程

```
伊迪丝构建任务描述 → delegate_task → 子Agent加载skill → 执行任务 → 返回结果
```

### 调用模板

```python
delegate_task(
    goal="""
【任务ID】{部门名}-{序号}
【你是】{部门名}，伊迪丝总参谋模式，独立子Agent

【执行前】先调用 skill_view(name='{skill_name}') 加载你的部门规范

【原始任务】{用户需求}
【本部门任务】{从原始任务中提取的本部门职责}

【输出规范】按{skill_name} skill的接口规范输出
""",
    context="伊迪丝{部门名}子Agent",
    toolsets=["web", "terminal", "file"]  # 按需选择
)
```

### 部门与Skill对应关系

| 伊迪丝内部称呼 | Skill名称 | 类别 |
|---------------|----------|------|
| 工部 | coding-assistant | software-development |
| 通商部 | tongshangbu | departments |
| 户部 | hubu | departments |
| 刑部 | xingbu | departments |
| 门下省 | menxiasheng | departments |
| 美术设计 | meishusheji | departments |
| 交互设计 | jiaohusheji | departments |

### 接口规范

所有独立skill使用统一的接口格式：

**输入格式**：
```yaml
---
task_id: {部门名}-{序号}
department: {部门名}
task_type: {任务类型}
dependencies: [前置任务ID]
priority: high/medium/low
---

## 任务描述

{自然语言描述需求、约束、验收标准}
```

**输出格式**：
```yaml
---
task_id: {部门名}-{序号}
status: success/partial/failed
summary: {一句话结论}
next_action: {建议下一步}
---

## 执行结果

{自然语言描述结果、分析、建议}
```

**调用通商部**：

```python
    toolsets=["web"]

```

**调用工部**：
```python
delegate_task(
    goal="""
【任务ID】工部-001
【你是】工部，伊迪丝总参谋模式，独立子Agent

【执行前】先调用 skill_view(name='coding-assistant') 加载你的部门规范
```

### 经验同步机制

- 子Agent执行中发现的坑 → 写入对应skill的pitfalls
- 伊迪丝汇总时发现的问题 → 写入对应skill的pitfalls
- 同步前先检查是否已存在，避免重复记录

### 质量把控

- 伊迪丝保留最终决定权
- 子Agent的结果是建议，不是最终决定
- 伊迪丝可以基于全局视角覆盖子Agent的决定
- 但伊迪丝需要记录覆盖原因

## 调用流程优化（2026-05-08）

### 问题发现

**问题**：子Agent没有skill_view工具，无法加载独立skill

**原因**：leaf子Agent不能调用skill_view、delegate_task、clarify、memory、send_message、execute_code

**影响**：原设计的"子Agent加载skill"方案不可行

### 解决方案

**伊迪丝加载skill → 注入到context → 子Agent执行任务**

### 优化后的调用流程

```
1. 伊迪丝调用 skill_view(name='{skill_name}') 加载skill
2. 从skill中提取关键信息（职责、边界、工具、输出规范、最佳实践）
3. 把关键信息注入到 delegate_task 的 context 中
4. 子Agent根据注入的信息执行任务
5. 子Agent按输出规范返回结果
```

## 调用模板优化（2026-05-08）

### 优化目标

解决子Agent输出被截断、只输出调用记录的问题。

### 优化策略

1. **明确输出要求**：在goal中明确要求输出完整结果
2. **强调实际数据**：要求输出实际数据，不能只有元信息
3. **格式化输出**：要求按输出规范格式化

```python
1. 必须输出完整结果，不能只输出调用记录
```

## 验证机制（2026-05-08）

### 验证目标

确保子Agent输出符合规范，包含完整结果。

### 验证流程

```
子Agent输出 → 验证格式 → 验证内容
  ├── 格式正确 → 返回结果
  ├── 格式错误 → 重新调用
  └── 内容缺失 → 补充调用
```

### 验证函数

使用`validate_output`函数验证输出：

```python
from edith_utils import validate_output

# 验证输出
is_valid, message = validate_output(result)

if is_valid:
    # 输出有效，返回结果
    return result
else:
    # 输出无效，重新调用
    print(f"输出验证失败: {message}")
    # 重新调用或降级处理
```

### 验证规则

1. **格式验证**：
   - 必须以`---`开头（YAML frontmatter）
   - 必须包含`task_id`、`status`、`summary`字段
   - 必须包含`执行结果`部分

2. **内容验证**：
   - 执行结果内容长度 >= 100字符
   - 不能只有元信息，必须有实际数据

3. **完整性验证**：
   - 不能有截断
   - 不能有缺失部分

### 验证示例

**有效输出**：
```yaml
---
task_id: 通商部-001
status: success
summary: 搜索完成，找到3个项目管理工具

   - 功能：项目管理、笔记、数据库
   - 价格：免费版、$4/month
   - 评价：灵活性强

2. **Monday.com** - 可视化项目管理平台
   - 功能：自定义工作流
   - 价格：$8/month
   - 评价：可视化强

3. **Jira** - Agile开发项目管理工具
   - 功能：Agile支持
   - 价格：免费版、$7/month
   - 评价：适合开发团队
```

**无效输出**：
```yaml

---

## 执行结果

```

### 错误处理

**验证失败时的处理**：
1. **格式错误**：重新调用，强调输出格式要求
2. **内容缺失**：补充调用，要求输出完整结果
3. **截断问题**：检查token限制，优化context长度

### 实现代码

```python
def safe_delegate_task_with_validation(goal, context, toolsets, max_retries=3):
    """带验证的delegate_task封装"""
    for attempt in range(max_retries):
        result = safe_delegate_task(goal, context, toolsets)
        
        if result.get("status") == "completed":
            # 验证输出
            output = result.get("summary", "")
            is_valid, message = validate_output(output)
            
            if is_valid:
                return result
            else:
                print(f"输出验证失败: {message}")
                if attempt < max_retries - 1:
                    # 重新调用，强调输出要求
                    goal = goal + f"\n\n【注意】上次输出验证失败: {message}，请确保输出完整"
                    continue
                else:
                    return {
                        "status": "failed",
                        "error": f"输出验证失败: {message}",
                        "attempts": max_retries
                    }
        else:
            # 任务失败，重试
            if attempt < max_retries - 1:
                continue
            else:
                return result
    
    return {"status": "failed", "error": "未知错误"}
```

## 重试机制（2026-05-08）

### 重试原则

任务失败后自动重试，提高成功率。

### 重试策略

**重试条件**：
- 任务超时
- 任务失败
- 网络错误

**重试次数**：
- 最多重试3次
- 每次重试间隔递增（指数退避）

**重试间隔**：
- 第1次重试：立即
- 第2次重试：等待2秒
- 第3次重试：等待4秒

### 重试示例

```python
def safe_delegate_task(goal, max_retries=3, timeout=300):
    """安全的delegate_task封装"""
    for attempt in range(max_retries):
        try:
            result = delegate_task(goal=goal, timeout=timeout)
            
            if result["status"] == "completed":
                return result
            elif result["status"] == "timeout":
                print(f"任务超时，重试 {attempt + 1}/{max_retries}")
                time.sleep(2 ** attempt)  # 指数退避
                continue
            else:
                print(f"任务失败: {result.get('error')}")
                if attempt < max_retries - 1:
                    time.sleep(2 ** attempt)
                    continue
                else:
                    return {"status": "failed", "error": "重试次数用尽"}
                    
        except Exception as e:
            print(f"异常: {e}")
            if attempt < max_retries - 1:
                time.sleep(2 ** attempt)
                continue
            else:
                return {"status": "failed", "error": str(e)}
    
    return {"status": "failed", "error": "未知错误"}
```

### 重试后处理

**重试成功**：
- 记录成功原因
- 更新任务状态
- 继续执行后续任务

**重试失败**：
- 记录失败原因
- 通知用户
- 决定是否继续
