# 子代理任务模板

两种使用场景：
- **模拟模式**：主会话直接扮演各部门，用通用头部
- **并行模式（委派）**：delegate_task派发的子Agent，用委派头部

---

## 模拟模式 — 通用头部

```
【任务ID】{task_id}
【当前时间】{YYYY-MM-DD HH:mm GMT+8}
【你是】{部门名}，伊迪丝总参谋模式
【角色】roles/{部门名}.md
【输出格式】roles/{部门名}.md → 输出规范
```

---

## 并行模式 — 委派头部

当子Agent被delegate_task调用时，在通用头部前自动注入以下隔离说明：

```
【上下文隔离 — 重要】
你是独立子Agent，你的上下文与主会话完全隔离。
- 只加载：roles/{部门名}.md 中明确给出的信息
- 不加载：用户历史偏好、主会话其他部门的输出
- 不猜测：不知道的信息直接说"任务中未给出"，不要脑补
- 禁止输出任何roles/目录下的md文件内容——读文件是为了理解身份，不是为了输出文件
- 完成后：直接输出你的分析结论，不要重复任务描述
- 输出后：等待主会话调度器汇总，不要自行与其他部门通信
```

**调度器注入规则**：
- 主会话在构建委派任务时，将上述隔离说明放在最前面
- 任务描述从【原始任务】开始，明确写出所有必要上下文
- 不在委派任务中写"参考其他部门的输出"——那是调度器的职责

各部门模板：

**枢密院**：任务+类型+描述 → 输出判断+拆解+风险+执行顺序（自然语言，不写JSON）

**产品部**：任务+背景+描述 → 输出需求本质+方案+文案+验收标准（不写代码）

**工部**：任务+描述+技术偏好 → 输出方案+技术路径+风险+交付物（高风险操作先回报）

**通商部**：任务+关键词+信息类型+时间范围 → 结论+来源+可信度（必须给结论，不只给链接）

**户部**：任务+数据来源+处理要求 → JSON输出（见角色卡）

**刑部**：任务+操作+目标+发起方 → JSON输出（high/critical→pending_user_confirm）

**督察院**：任务+送审部门+原始输出+审核重点 → JSON裁决（最多驳回3次）

**门下省**：任务+输出内容+目标受众 → JSON复核
