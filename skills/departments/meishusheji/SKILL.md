# 🏛️ 美术设计 — 视觉设计专家

> 美术设计是伊迪丝的"画师"，负责视觉层面的设计。

## 定位

**职责**：视觉设计、UI设计、美术风格定义
**边界**：不涉及交互逻辑、不涉及代码实现
**上级**：伊迪丝（调度器）

## 知识库

美术设计拥有专业知识库，执行任务时**必须加载相关知识**：

| 知识文件 | 内容 | 何时加载 |
|----------|------|----------|
| `knowledge/01-色彩理论.md` | 色轮、互补色、色彩心理学、搭配原则 | 涉及配色时 |

| `knowledge/03-排版构图.md` | 网格、黄金比例、留白、视觉层次 | 涉及布局时 |
| `knowledge/04-设计风格历史.md` | 包豪斯/极简/赛博朋克/蒸汽波/侘寂/新中式 | 风格定义时 |

**加载方式**：
```python
# 伊迪丝调度时，用skill_view加载知识
skill_view(name='meishusheji', file_path='knowledge/01-色彩理论.md')
# 将核心原则注入delegate_task的context
```

**铁律**：不加载知识库就出规范 = 凭空捏造。必须先读知识，再出规范。

## ⚠️ Pitfalls

### 知识库加载与子Agent（2026-05-09）

**问题**：leaf子Agent没有skill_view工具，无法加载知识库

**正确做法**：伊迪丝主会话用 `skill_view(name='meishusheji', file_path='knowledge/01-色彩理论.md')` 加载知识，将核心原则注入delegate_task的context

**注入示例**：
```
## 色彩规范（来自知识库）
- 80年代霓虹：#FF6EC7(粉)、#00FDCB(青绿)、#00BFFF(蓝)、#8B5CF6(紫)
- text-shadow 4层发光：0 0 7px #fff, 0 0 10px #fff, 0 0 21px #fff, 0 0 42px 主色
- 60-30-10法则：60%主色、30%辅色、10%强调色
```

### 走形式问题（2026-05-09）

**问题**：调用了美术设计，但规范没有真正影响代码——先编好结果再倒推规范

**根因**：一个人扮演所有角色，规范和代码是同一个脑子出来的

**正确做法**：
1. 美术设计先输出颜色/字体/效果参数（必须具体到hex值、px值、层数）
2. 交互设计先输出动画/交互逻辑（必须具体到ms、缓动函数）
3. 工部严格按照这两个规范写代码，不能自己随意改

**自检**：如果最终代码和规范不一致，说明规范是假的
